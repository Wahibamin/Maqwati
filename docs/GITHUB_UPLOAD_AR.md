# دليل نشر مقوتي على GitHub

## قبل النشر

1. راجع مجلد `lib/` وأي إعدادات محلية للتأكد من عدم وجود مفاتيح أو أرقام هواتف شخصية.
2. لا تنشر بيانات العملاء أو الموردين الحقيقية، أو قواعد SQLite الفعلية أو الأرشيفات الاحتياطية.
3. أضف صور الواجهات الحقيقية لاحقًا بعد التأكد من أنها تخص الإصدار المتقدم.
4. راجع `docs/TEST_STATUS_AR.md` ولا تصف المشروع بأنه جاهز تجاريًا دون تحقق ميداني إضافي.
5. ضع ترخيصًا فقط إذا قررت صراحة السماح للآخرين بإعادة استخدام الكود؛ المستودع العام لا يعني أن الشيفرة مفتوحة الترخيص.

## خطوات GitHub عبر المتصفح

1. أنشئ مستودعًا جديدًا باسم `maqwati-accounting-app`، ويفضل **Public** إذا أردت مشاركته في ملف التوظيف.
2. لا تضف README تلقائيًا أثناء الإنشاء؛ الملف موجود بالفعل.
3. فك ضغط حزمة المراجعة، ثم ارفع **محتويات مجلد `Maqwati`** إلى جذر المستودع (بما فيها `lib/` و`android/` و`test/` و`README.md`).
4. لاحظ أن رفع عدد كبير من الملفات عبر المتصفح قد لا يكون مناسبًا دائمًا؛ يمكن استخدام Git محليًا إذا لزم.
5. بعد الرفع، افتح صفحة المستودع وتأكد من ظهور README والروابط في مجلد `docs`.

## وصف مختصر للمستودع

**مقوتي — تطبيق Flutter عربي لإدارة مبيعات ومشتريات البائعين والموردين والزبائن والديون والمخزون والمصاريف، يعمل محليًا باستخدام Drift/SQLite.**

## تذكير مهم

هذه حزمة **Source Portfolio** وليست حزمة إصدار موقّعة للمستخدم النهائي. لا ترفق مفاتيح التوقيع أو PIN حقيقي أو إعدادات Google الحساسة. قد يتطلب البناء تنزيل اعتماديات Flutter/Gradle إذا لم تكن مثبتة على الجهاز.

## معرض الصور الذي أُضيف في الإصدار النهائي

أصبحت الصور موجودة في `screenshots/` مع روابط Markdown في `README.md`، ويجب رفع المجلدين في المستودع نفسه حتى تظهر المعاينة تلقائيًا. تأكد من نشر **محتويات مجلد Maqwati** وليس ملف ZIP وحده.

**ملاحظة:** لا تُرفع قاعدة بيانات الجهاز أو صور العملاء الأصلية. إذا قررت مشاركة صور جديدة في المستقبل، احجب بيانات الاتصال والأرصدة أولًا.
